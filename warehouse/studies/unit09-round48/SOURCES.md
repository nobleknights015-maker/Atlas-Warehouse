# Round48 primary-source research ledger

2026-11-13. Twenty-two selected primary pages/source listings were examined with the access limits below. Reused Round44's 21-source homework and actual warehouse checkpoints rather than discarding them. Several sources overlap: these are not 43 unique new studies. Broad search results were screened for original authors, official docs and inspectable code. This is a substantial scoped search, not a claim to exhaust every website. No paywalled videos, pirated books, paid generators or third-party character art were used.

## Ryan Juckett — Analytic Two-Bone IK

https://www.ryanjuckett.com/analytic-two-bone-ik-in-2d/

Access: Read derivation and complete licensed sample. Ported and executed; attribution/license retained.

Project application: Solver controls bend and reports reach failure; it does not define a walking schedule or draw hidden armor.

## Manning Krull — Walking

https://manningkrull.com/__pixel-art/walking.php

Access: Read 2/4/8-frame sections and original creator explanations.

Project application: Independent camera-depth layers, phase-shifted leg cycles, heel/toe action, and native contour cleanup.

## Pedro Medeiros — Simple Walk Cycle

https://www.patreon.com/saint11/posts/simple-walk-14234033

Access: Read public text; embedded animation not watched.

Project application: Work out legs before complicating arm animation; frame counts are a choice rather than quality proof.

## AnimSchool — Walk Cycle Animation Tips

https://blog.animschool.edu/2024/03/14/walk-cycle-animation-tips/

Access: Read instructor article; video not watched.

Project application: Contact, down, passing and up describe functional phases; inspect spacing and balance.

## Animation Mentor — Basic Human Walk Cycle

https://www.animationmentor.com/blog/tutorial-animating-human-walk-cycle/

Access: Read article; embedded video not watched.

Project application: Plan opposite contact and breakdown poses; linear grounded foot translation avoids sliding.

## Spine — Spineboy

https://esotericsoftware.com/spine-examples-spineboy

Access: Read hip/legs hierarchy explanation; Spine editor not installed or executed.

Project application: Keep foot targets independent of hip motion; solve leg before foot orientation.

## Spine — Weights

https://esotericsoftware.com/spine-weights

Access: Read ownership, binding and ordering documentation.

Project application: Influence ownership and draw depth are separate. A correct solver cannot repair the wrong material assignment.

## Spine — Meshes

https://esotericsoftware.com/spine-meshes

Access: Read geometry and deformation documentation.

Project application: Designed topology matters; automatic bending is not automatically good-looking.

## Spine — Region Attachments

https://esotericsoftware.com/spine-regions

Access: Read sequence and translation sections.

Project application: Use discrete pose-specific images when a single deforming texture is inadequate.

## Spine — Skins

https://esotericsoftware.com/spine-skins

Access: Read reuse concepts and attachment independence.

Project application: Reuse motion semantics with compatible attachments; new characters still need silhouette/fit review.

## Godot — 2D Skeletons

https://docs.godotengine.org/en/stable/tutorials/animation/2d_skeletons.html

Access: Read polygon, ordering, bone, weighting and internal-vertex sections; page flags version caveat.

Project application: Unexpected bends require designed geometry. This is study, not an engine migration.

## Godot — Cutout Animation

https://docs.godotengine.org/en/stable/tutorials/animation/cutout_animation.html

Access: Read pivots, hierarchy, depth and mixed cel/cutout workflow; version caveat applies.

Project application: Separate transform hierarchy from drawing order; author replacement cels for difficult features.

## Godot — TwoBoneIK

https://docs.godotengine.org/en/stable/classes/class_skeletonmodification2dtwoboneik.html

Access: Read algorithm/properties; experimental API not integrated.

Project application: Independent confirmation of two-link geometry, bend direction and reach limits.

## Godot — 2D Sprite Animation

https://docs.godotengine.org/en/stable/tutorials/2d/2d_sprite_animation.html

Access: Read image/sheet playback tutorial.

Project application: Keep animation images and timing explicit; no runtime integration claim.

## Aseprite — Rotate

https://aseprite.org/docs/rotate/

Access: Read pivot and Fast Rotation/RotSprite documentation.

Project application: Rotation method is a raster-quality choice, not an anatomy or gait solution.

## Aseprite — Onion Skinning

https://aseprite.org/docs/onion-skinning/

Access: Read reference-frame configuration.

Project application: Compare neighboring silhouettes and volumes while making targeted repairs.

## Aseprite — Animation

https://aseprite.org/docs/animation/

Access: Read frame/layer/duration workflow.

Project application: Editable cels, timing and playback are distinct parts of a deliverable.

## Aseprite — Tags

https://aseprite.org/docs/tags/

Access: Read animation ranges and playback direction.

Project application: Separate four cardinal clips in a layered file.

## Aseprite — Sprite Sheets

https://aseprite.org/docs/sprite-sheet/

Access: Read import/export layout documentation.

Project application: Frame dimensions, offsets and tag ranges must be recorded.

## Pillow — ImageTransform

https://pillow.readthedocs.io/en/stable/reference/ImageTransform.html

Access: Read affine inverse mapping documentation; Pillow executed.

Project application: Use a true rigid matrix for armor; nearest sampling avoids blended colors but still needs contour review.

## RotSprite Rust source

https://docs.rs/rotsprite/latest/src/rotsprite/lib.rs.html

Access: Read scale2x/rotation source listing and package overview. Not executed; no Rust compiler used.

Project application: Pixel-aware rotation is available, but cannot fix limb ownership, hidden surfaces or missing steps.

## McGuire/Gagiu — MMPX

https://www.jcgt.org/published/0010/02/04/paper.pdf

Access: Read indexed primary abstract and figure description only; full algorithm not evaluated or executed.

Project application: Magnification/rotation preprocessing is a different problem from authoring a walk.
